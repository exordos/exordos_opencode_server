# Exordos OpenCode Server

`opencode_server` is an Exordos element that runs a pinned, authenticated
[OpenCode Server](https://github.com/anomalyco/opencode) on a dedicated VM.
OpenCode state and the server workspace live on the element's persistent data
disk.

The repository does not vendor OpenCode source code or binaries. During the VM
image build, the installer downloads OpenCode `1.18.31` from the upstream GitHub
release and verifies the archive with a pinned SHA-256 checksum.

## Connection exports

The server listens on TCP port `4096` on the VM network interface and uses HTTP
Basic Auth. The element exports three resources:

| Export | Resource | Consumer field |
|---|---|---|
| `endpoint` | read-only Values Store variable | `value` (`http://<vm-ip>:4096`) |
| `login` | read-only Values Store variable | `value` (`opencode`) |
| `password` | Secret Manager password | `value` |

The password is generated by Exordos Secret Manager with `AUTO_URL_SAFE`. It is
injected into a root-owned environment file on the VM and is not stored in this
repository or in the built image.

All managed resources currently carry the fixed platform project ID required by
the deployment API. This is a temporary platform compatibility constraint, not
a user-supplied deployment parameter.

The exported endpoint is plain HTTP. Use it only on a trusted network, or put a
TLS-terminating authenticated proxy in front of it before exposing it to an
untrusted network.

## Development

```bash
uv sync --all-extras
make check
```

`make check` runs the manifest regression tests, Ruff, and Bash syntax checks.

## Build

Build the element with the Exordos CLI:

```bash
make build
```

The generated element is named `opencode_server`. See the official Exordos
documentation for [element builds](https://exordos.github.io/exordos_core/app-developer-guide/build.html),
[manifests](https://exordos.github.io/exordos_core/em/manifest.html), and
[Secret Manager passwords](https://exordos.github.io/exordos_core/secret/passwords.html).

## Release

The `Exordos element` GitHub Actions workflow builds the complete VM image on
branch pushes, external pull requests, release tags, and manual runs. Every
branch push publishes its immutable dev version to the configured Exordos
element repository without changing `latest`. A pushed stable SemVer tag
(`MAJOR.MINOR.PATCH`) publishes the stable version and updates `latest`. Both
publication paths require `tests.yaml` to pass for the exact same commit.

Publication uses the repository or organization Actions secret `PUSH_CFG`. Its
value must be the base64-encoded contents of an `exordos.push.yaml` file. All
published versions are immutable: the workflow deliberately does not use
`exordos push --force`. Internal pull request events skip a duplicate image
build because the same commit is already built and published by its branch-push
run. External pull requests and manual runs build and verify the complete image
but do not publish it.

## Runtime behavior

- OpenCode automatic updates and session sharing are disabled.
- Basic Auth is required for every server request.
- A dedicated `opencode` system user and group run the service.
- State, caches, data, and the workspace are stored under
  `/var/lib/opencode_server` on the persistent disk.
- Bootstrap reports success only after an authenticated health check passes.

OpenCode provider credentials and model selection remain OpenCode runtime
configuration; they are intentionally not embedded in this generic element.
